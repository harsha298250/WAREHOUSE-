# Database Migration Guide

This guide details the procedures for database configuration, migration creation, schema updates, and rollback operations using Alembic for the Smart Warehouse Automation platform.

---

## 1. Local Database Setup
1. **Database Service**: Install MySQL Community Server or start MySQL via a service runner (e.g. XAMPP, WAMP, or local Docker container).
2. **Database Schema**: Create a blank database user and schema:
   ```sql
   CREATE DATABASE warehouse_db;
   CREATE USER 'warehouse_app'@'localhost' IDENTIFIED BY 'YOUR_SECURE_PASSWORD';
   GRANT ALL PRIVILEGES ON warehouse_db.* TO 'warehouse_app'@'localhost';
   FLUSH PRIVILEGES;
   ```
3. **Environment Setup**: Copy `.env.example` to `.env` and fill in the database URL credentials:
   ```env
   DATABASE_URL=mysql+pymysql://warehouse_app:YOUR_SECURE_PASSWORD@localhost:3306/warehouse_db
   ```

## 2. Creating Migrations
When SQLAlchemy models in `backend/models.py` are added or updated, generate a new Alembic migration script:
```bash
alembic revision --autogenerate -m "describe_your_changes_here"
```
A new migration script will be written to the `alembic/versions/` directory.

## 3. Reviewing Migrations
> [!IMPORTANT]
> **Always inspect autogenerated migration files before applying them!**
> Alembic's autogenerate detects most table, column, index, and constraint changes, but it may miss database-specific types or constraint names. Inspect the file in `alembic/versions/` to verify that `upgrade()` and `downgrade()` code blocks are correct and safe.

## 4. Applying Migrations
Apply all pending database migrations up to the latest revision (head):
```bash
alembic upgrade head
```

## 5. Checking Current Revision
To check the current migration state of the active database connection:
```bash
alembic current
```
To view the full chronological history of migration revisions:
```bash
alembic history --verbose
```

## 6. Rollback Procedures
To revert the database schema by exactly one migration step:
```bash
alembic downgrade -1
```
To revert the database to a specific historical migration revision:
```bash
alembic downgrade <revision_id>
```
To revert all migrations and drop all tables (Warning: destructive):
```bash
alembic downgrade base
```

## 7. Production Migration Procedure
> [!CAUTION]
> **Never run Base.metadata.create_all() or database reset commands in production.**
> Production table schemas must be managed strictly using Alembic migrations:
1. **Pre-Deployment Backup**: Export a full MySQL backup before applying any new migrations:
   ```bash
   mysqldump -u warehouse_app -p warehouse_db > pre_deploy_backup.sql
   ```
2. **Migration Run**: Run `alembic upgrade head` before the backend application starts. In the production container, this is handled automatically via the entrypoint script:
   ```bash
   alembic upgrade head
   ```
3. **Rollback Option**: If deployment checks fail, immediately run `alembic downgrade -1` and restore the backup file.

---

## 8. Warning Against Destructive Resets
* **Schema Creation**: Do not re-inject `Base.metadata.create_all` into production scripts or startup files. Let Alembic manage schemas.
* **Data Loss Prevention**: Never call `Base.metadata.drop_all()` or drop tables manually in production. Use Alembic migrations to alter/drop columns gracefully.
